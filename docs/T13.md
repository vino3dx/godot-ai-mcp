# T13：Godot Agent Intelligence 与 Native Layer

本文合并 T13 阶段的架构、ClassDB/GDScript Intelligence、Native Editor 计划、UI 能力和测试记录。状态词含义如下：

- `IMPLEMENTED`：代码已经实现。
- `UNIT_TESTED`：已有自动化单元测试覆盖。
- `INTEGRATION_TESTED`：组件已组合验证。
- `ENGINE_VERIFIED`：已有真实 Godot Editor/Runtime 证据。
- `BLOCKED`：所需引擎或环境不可用。
- `PLANNED`：计划中，尚未实现。

## T13 总体目标

godot-ai-mcp 的目标是让 Agent 通过 MCP 理解和驱动 Godot 项目。能力按上下文区分：

```text
Agent workflow
  -> MCP Tool / ToolHost
  -> context-aware Service
  -> Native Layer (Editor/Runtime) or File Layer (Disk)
  -> Godot Engine / project files
```

每个结果都应明确属于 `editor`、`runtime` 或 `disk` 上下文。

ClassDB 元数据和对象真实状态必须区分：

- `GodotApiService` 描述从引擎 dump 得到的 ClassDB 元数据。
- Native Service 将来描述实时 Node/Resource 实例。
- 解析 `.tscn`/`.tres` 只描述磁盘状态。

Native 对象引用必须限定在 Bridge Session 内。Godot instance ID 不是跨会话永久标识。

## 系统架构与当前边界

当前实现仍未合并 File、Runtime、Editor 三种通道，也未提供 Native Scene/Node 写操作。

Native Bridge 是基础设施，不等于 Native Editor 能力。所有 Native 能力必须分别通过 Godot Standard 和 Godot .NET 验证；Standard 的结果不得复用为 .NET 证据。

## ClassDB 与 GDScript Intelligence

### ClassDB

`GodotApiService` 加载并缓存引擎生成的 `extension_api.json`，当前可提供：

- 类名。
- 继承关系。
- 是否可实例化。
- 属性。
- 信号。
- 枚举关联。
- 方法。
- 方法参数和默认值（仅在 dump 提供时）。
- 属性 getter/setter 名称。
- 常量。
- 直接成员与继承成员视图。

T13-A5 扩展了导入模型，并保留 `engine_dump` 验证状态及缓存/版本来源。

Godot dump 不可靠提供的 `hint`、`hint_string`、`usage` 和默认值必须保持缺失，不能猜测。

当前工具：

- `class_get_info`
- `class_search`
- `class_validate_member`

这些工具查询的是 ClassDB 元数据，不代表实时 Editor 对象状态；没有 Godot 可执行文件时返回结构化 `GODOT_NOT_FOUND`。

状态：`IMPLEMENTED`、`UNIT_TESTED`；真实引擎验证受环境限制，当前为 `BLOCKED`。

### GDScript 静态分析

`ScriptService` 当前返回：

- `extends` 与 `class_name`。
- `@tool`、`@icon`、`@static_unload` 等脚本注解。
- 导出变量及其注解。
- 信号及参数声明。
- 枚举及显式值。
- 常量、类型和值。
- 顶层函数、静态状态、参数、默认值和返回类型。
- 变量及符号位置。

静态结果不是引擎加载结果。脚本有效性、自定义类注册和真实 Node 绑定仍需要 Godot 验证。

状态：`IMPLEMENTED`、`UNIT_TESTED`。

### 项目级 GDScript 关系图

`GdscriptProjectService` 聚合脚本和场景解析器，建立 disk-context 项目图，记录：

- 继承关系。
- `preload()` / `load()`。
- `$NodePath`。
- `%UniqueName`。
- `get_node()`。
- `@onready`。
- 脚本绑定。
- 信号定义、发射、连接和断开。
- 场景序列化信号连接。

每条关系包含 source、target、relation type、source location、confidence、context 和 resolution status。动态表达式明确标记为 `dynamic`/`unknown`，不能作为引擎事实。

状态：`IMPLEMENTED`、`UNIT_TESTED`；不依赖真实引擎验证。

## Native Editor Bridge

EditorPlugin/TCP Bridge 当前只提供基础设施和预期的 `project_capabilities` 请求形状，真实 Godot Editor 验证仍为 `BLOCKED`。

尚未实现：

- 实时 Editor SceneTree 查询。
- 实时 Node/Resource 对象引用。
- Node 属性写入。
- Owner、Signal、Group 和场景保存操作。
- Editor Undo/Redo 集成。

Native Editor 验收必须分别执行：

1. Godot Standard。
2. Godot .NET。

当前环境中两种 Godot Editor 可执行文件均不可用，因此不能宣布 Native Bridge 或 Native Editor 兼容完成。

## Control / UI Intelligence

当前 UI 能力按上下文划分：

- `disk`：`scene_set_ui_layout` 写入序列化 Control 属性。
- `runtime`：`runtime_inspect_ui` 测量布局完成后的真实矩形并报告布局问题。
- `editor`：Native Editor Control 检查尚未实现，依赖 Bridge 验证。

Container 语义、Theme 检查和 Editor 侧布局写入不能仅从静态文本推断。

状态：disk/runtime 能力已存在并有测试；editor 能力为 `BLOCKED`。

## 已知限制

- File Layer 的静态分析不能证明引擎运行时状态。
- ClassDB dump 元数据不能证明具体对象的实时状态。
- Native Bridge 尚无 Standard/.NET 双版本真实运行证据。
- Standard 通过不能推断 .NET 通过。
- 动态 GDScript 调用和运行时生成节点只能标记为 unknown/dynamic。
- Editor 未保存状态与磁盘 `.tscn` 状态可能不同。
