## 追加：git 基线 + Godot 版本核实

- **`git init -b main` 已完成，Stage 1 基线提交 `216beb8`**（54 文件，工作区干净）。`dist/`、`node_modules/`、`.workbuddy/` 均已被 `.gitignore` 排除。
- 新增 `.gitattributes`：`* text=auto eol=lf` + 常见二进制扩展名标记。原因：全局 `core.autocrlf=true` 会让 checkout 把文件改成 CRLF，而 T2 要做字节级无损往返，行尾被改写会产生假失败。Godot 自身各平台都写 LF，固定 LF 才与引擎一致。
- 用户确认：-32602 保持现状；移除 `zod`、新增 devDep `@modelcontextprotocol/client` 均接受。
- **核实：Godot 4.7.2-stable 真实存在**，2026-08-18 作为维护版本发布（4.7 于 2026-06-18 发布）。目标版本无需调整。
- **重要发现（说明"凭记忆写 fixtures"不可靠）**：抓取 `godotengine/godot` 标签 `4.7.2-stable` 的 `scene/resources/resource_format_text.cpp` 后，作者逻辑里 `ResourceFormatSaverTextInstance::save()` 构造头部时**并不写 `load_steps`**（`[gd_scene format=M uid="..."]` / `[gd_resource type="..." format=M uid="..."]`），与"`load_steps` 是 saver 写出的"这一常见认知不符。同时确认了 ext_resource / sub_resource / node / connection 的确切字段顺序（见下）。→ 结论：fixtures 必须来自真实引擎输出或逐条对照源码，不能凭记忆手写。
