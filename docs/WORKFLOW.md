# godot-ai-mcp 工作流规则(每个任务开工前必读,权威版本)

本文件是所有接力模型的统一规则,优先级高于 HANDOFF.md 里的旧版"固定规则"。冲突时以本文件为准;任务卡的具体要求高于本文件的通用条款。
管理者(Claude)只做规划与验收;你负责执行。**你的回报会被逐条核对,编造证据比承认"没做完"代价大得多。**

## 1. 开工协议(省 token)
1. 必读:本文件 + 当前任务卡(docs/PLAN_PROMPTS.md 里对应阶段)。
2. 按需读:docs/AGENTS.md(涉及分层/错误码/并发时)、docs/architecture.md 的相关章节、`.workbuddy/memory/MEMORY.md` 的「已核实事实」段。不要通读全部文档,不要整文件 cat 大文件,用 grep / 行范围读取。
3. `git status --short` 必须干净,否则停下报告。记录起点提交:`git rev-parse --short HEAD`(回报要用)。
4. 动手前先写一份**不超过 10 行**的计划:改哪些文件、新增哪些测试、哪些不碰。然后直接执行,不要把计划扩写成长文。

## 2. 红线
- 不改弱/删除/跳过现有测试,不为让测试通过而改被测断言。
- 不改 `tests/architecture.test.ts`;不改 `src/core/concurrency/`、`src/mcp/`(任务卡明确要求的除外,并在回报里写明依据哪一条)。
- 不新增依赖,不用 `console.log`,不整文件重写已有文件。
- 不顺手重构、不顺手修"看起来不对"的别处代码——记进回报的【风险与未验证项】即可。
- 不 push,不改 git 配置,不删除本地未跟踪文件。
- Tool 只做 Schema/校验/调 Service;文件与解析在 core,业务在 services;失败一律抛 `GodotMcpError`。

## 3. 防幻觉(最重要)
**事实来源优先级**:① `tests/fixtures` 真实文件 ② 已安装依赖的 `.d.ts` / 源码 ③ Godot 4.7.2 源码(按 MEMORY 里的标签地址取) ④ 官方文档 ⑤ `godot --help` 等真实 CLI 输出。**你的记忆不是来源。**

- 凡涉及以下内容,写代码前必须先找到来源,并在代码注释或 docs 里留下来源(文件名+行号 / URL):
  Godot 文件格式字段与顺序、Variant 文本写法、UID 规则、Godot CLI 选项、引擎类/属性/信号名、MCP SDK 的 API、Node 与 TypeScript 的不常用 API。
- 找不到来源 → **停止该部分**,在回报【需要你决定】里写:不确定点 + 你需要我提供什么 + 你的默认选择。禁止"先按常识写个版本"。
- 每条结论都标注:**已实测**(贴命令与输出)/ **仅推断**。没跑过的不得写"已验证"。
- 写完 API 调用后,用 `tsc` 与测试确认它真实存在;不要因为"编译器没报错"就当作行为正确。
- 不得声称"测试通过"而不贴 `npm test` 的原始输出。

## 4. 防绕圈
- 同一个失败,最多换 **3 种不同假设**尝试。每次尝试先写一行:`假设 → 验证命令 → 结果`。第 3 次仍失败 → 状态记为 BLOCKED,回报现象、已排除的假设、最小复现命令,然后停下。
- 不重复运行同一条已失败的命令期待不同结果。
- 测试失败:先完整读错误信息,定位是实现错还是测试错;实现错就改实现。
- 连续 3 次工具调用没有获得新信息 → 停下,换思路或报告。
- 不在"最优方案"上反复权衡:设计性分歧选最简单可靠的一个,在回报里写一句理由,继续。
- 范围蔓延信号(想"顺便"加功能、想"以后会用到"、想抽象一层):一律不做,记入回报。

## 5. 防过度思考
- 先做最小可运行版本(MVP),再补边界。一个提交只含一个任务。
- 能用一个现有函数解决的,不新建抽象。三处重复以内不抽象。
- 回报与文档里不复述任务卡,不写过程叙事,不写大段解释性文字。
- 代码紧凑,少空行;沿用现有命名与结构。

## 6. 本项目高发幻觉点(逐条警惕)
1. `.tscn/.tres/project.godot` 的字段顺序、`load_steps`、UID、`binds=` 后的空格等细节——已被实测推翻过一次"常识"。
2. MCP SDK:包是 `@modelcontextprotocol/server@2.x`,API 与 v1 的 `@modelcontextprotocol/sdk` 不同;`inputSchema` 必须是 Standard Schema 契约;入参校验的唯一权威是 ToolHost。不要凭 v1 记忆改。
3. Godot CLI 选项:以 `tests/fixtures/godot-help.txt` 为准,不凭记忆写 flag。
4. `extension_api.json`:不要假设里面有属性默认值或编辑器专属类,先检查实际字段。
5. 本机可能是 Windows:路径用 `node:path`,锁 key 必须规范化(已有 `normalizeLockKey`),`rename` 覆盖与子进程树的终止行为不同于 Linux,不要想当然。
6. 行尾:仓库规定 LF;`tests/fixtures/**` 为 `-text`,字节必须原样。
7. GDScript 生成:制表符缩进;函数与 `@export` 变量上方用 `##` 文档注释,普通注释用 `#`。

## 7. 提交规范
- 一个任务一个提交,信息格式:`P<编号>: <一句话>`。
- 完成后在 `docs/HANDOFF.md` 对应任务行标注已完成,并加一句不超过 2 行的结论;不改其他内容。
- 阶段对照:P1≈T3前半、P1b 磁盘锁、P2=T1、P3a=T2、P3b=Variant、P4=T3/T4、P5=T5、P6=T6、P7a=类元数据、P7b=T7、P8=Script、P9=T8、P10=T9。

## 8. 需要决定时
不要停下来干等。把问题写进回报【需要你决定】,每条给出**你的默认选择**;在不触碰红线与来源规则的前提下,先按默认继续做可以做的部分。涉及"找不到来源的格式事实"除外,那种必须停。

## 9. 回报模板(唯一格式,总长 ≤ 60 行)
只按下面格式输出。命令输出一律贴**原始文本**,不要转述。

```text
【状态】DONE / PARTIAL / BLOCKED
【提交】<git log --oneline -3 原始输出>
【工作区】<git status --short 原始输出>
【测试】<npm test 2>&1 | tail -8 原始输出>
【改动】<git diff --stat <起点提交>..HEAD 原始输出>
【越界检查】<git diff --name-only <起点提交>..HEAD | grep -E "^(src/mcp/|src/core/concurrency/|tests/architecture)" 原始输出;有输出必须写任务卡哪一条允许>
【偏离任务卡】逐条:任务卡要求 X → 我做了 Y → 原因 Z;没有写"无"
【没做】逐条,每条写原因
【风险与未验证项】逐条,标注 已实测 / 仅推断
【需要你决定】编号;每条含默认选择;没有写"无"
```
